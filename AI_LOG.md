# AI_LOG

## Инструменты

- **Claude (Opus 5.5) в claude.ai** с доступом к shell — первая версия: разбор задания, код, тесты.
- **Claude Code (Opus 5.5), десктоп-приложение** — ревью первой версии, исправления, Alembic, CI.
- Правила для ассистента лежат в `CLAUDE.md`: деньги только `int`, переходы только через
  `ALLOWED_TRANSITIONS`, смена статуса условным `UPDATE`, тест на каждое изменение логики.

## Ключевые запросы

1. **Разбор задания до кода.** Дал PDF и попросил не писать код, а оценить объём и найти места,
   где легко ошибиться. Получил список рисков: распределение копеек в графике, гонка при
   идемпотентности, подпись от сырого тела, тот же ключ с другим телом. Этот список стал
   чек-листом для тестов.
2. **Реализация.** Попросил собрать проект по заданию и бонусам. Контекст: PDF целиком,
   «деньги только int», чистую логику держать отдельно от БД, чтобы тестировать её напрямую.
   Проверка — не только pytest, но и живой сервер с примерами curl из README.
3. **Ревью во второй сессии.** Дал готовый репозиторий и PDF: «проверь всё по заданию, найди,
   что сломается, исправь и доделай бонусы». Попросил не верить зелёным тестам, а пробовать
   сломать API руками: огромные числа, пустые строки, `true` вместо числа, лишние поля.

## Где модель ошиблась или предложила слабое решение

- **`created_at` терял таймзону.** SQLite хранит datetime без зоны, API отдавал время без `Z` —
  клиент прочитал бы его как локальное. Тесты не ловили: ответ POST брался из объекта в памяти.
  Заметили только на живом curl. Исправлено в `PaymentOut`, проверка добавлена в тест.
- **Переусложнённый вебхук.** Первая версия читала тело вручную и сама перевыбрасывала ошибку
  валидации. Не нужно: FastAPI кэширует тело, зависимость с подписью и параметр-схема читают
  одни и те же байты. Упростили до `data: WebhookIn`.
- **Пять мест, где вход давал 500 или молча принимался** — 78 зелёных тестов этого не видели,
  нашлось только ручным перебором краевых входов:
  - `tariff_id` или `payment_id` больше 2⁶³ → `OverflowError` в драйвере → **500**;
  - пустой `Idempotency-Key` записывался в уникальную колонку, повтор → `IntegrityError` → **500**;
  - `"tariff_id": true` создавал платёж за тариф 1 (lax-режим Pydantic приводит bool к int);
  - `"amount": 1` в теле молча игнорировался — клиент мог думать, что задал сумму;
  - фильтр по email зависел от регистра.

  Исправил строгими типами, `extra="forbid"`, ограничениями на заголовок и проверкой диапазона id.
  На каждый случай — тест. Чтобы убедиться, что тесты ловят именно эти баги, откатывал каждое
  исправление по отдельности и смотрел, какой тест падает.
- **Нарушала собственные правила.** `CLAUDE.md` требует, чтобы `services.py` не знал про HTTP,
  а модель импортировала туда `RequestValidationError` из FastAPI. Заменили на доменное
  исключение `TariffNotFound`, которое `main.py` превращает в стандартную 422.
- **Docker без `.dockerignore`** — `COPY . .` унёс бы в образ локальный `.venv` и `kvitto.db`.
- **Сырая автогенерация миграции** — Alembic создал её с лишним `batch_alter_table` и строками
  длиннее лимита ruff. Переписал вручную и добавил тест, что схема после миграций совпадает
  с моделями: если поменять модель и забыть миграцию, тест упадёт.

## Как проверял

- 105 тестов: суммы графика для всех тарифов × сроков × с промокодом и без; запрещённые переходы
  с проверкой, что статус не изменился; повтор ключа с подсчётом строк прямо в БД; краевые входы.
- Свежая установка по README в чистой копии репозитория на Python 3.11 — тесты и ruff проходят.
- Живой `uvicorn` с файловой БД: все curl из README, подпись вебхука, перезапуск поверх
  существующей базы (миграции не падают повторно, данные на месте).
- `ruff check`, `ruff format --check`, `alembic check` — без замечаний.
- Сам прошёл все сценарии в Swagger: промокод в нижнем регистре, график рассрочки
  (`[663334, 663333, 663333]` и ровный `[597000, 597000, 597000]` с промокодом), повтор ключа,
  запрещённый переход с проверкой, что статус не изменился, ошибки 422 с разбором `loc`/`msg`.
- Подпись вебхука проверил curl'ом с `WEBHOOK_SECRET`: без подписи и с поддельной — 401
  и статус `pending`, с подписью от `openssl dgst -hmac` — 200 и `succeeded`.
- Поднял `docker compose up` локально (OrbStack). Сначала запросы из браузера не доходили до
  контейнера: старый `uvicorn` слушал `127.0.0.1:8000`, а Docker — `*:8000`, и браузер попадал
  в `uvicorn`. Заметил по логам — в контейнере были только healthcheck'и. Вывод: один порт —
  один сервер.
- CI на GitHub: бейдж в README и таблица результатов pytest на странице каждого запуска.
  Проверил, что при сломанном `split_schedule` отчёт показывает именно упавшие тесты.
